## 目的

R35 板测已经确认 DDR 回读之后存在速率失配：DDR user clock 约 133.333 MHz，而 2-lane MIPI TX byte clock 约 75.008 MHz。R35 日志中 relay FIFO 曾满，TX packetizer 置位 overflow，且每帧只完成约 0x19B 行。因此 R36 在 token 传递链路增加下游反压，让 DDR cache 在 TX/relay 暂时不能接收时保持当前 token，不继续推进读指针。

## RTL 修改

- `fpga/uisrc/01_rtl/ddr/ddr_triple_frame_cache.v`
  - 增加 `out_ready`。
  - `out_frame_start`、`out_word_valid`、`out_line_end`、`out_frame_end` 只在下游 ready 时推进。
  - 下游暂停时保持当前 DDR 输出 token，避免丢 word、行尾或帧尾。
- `fpga/uisrc/01_rtl/csi2/csi2_tx_packet.v`
  - 增加 `O_data_ready`、`O_pkt_ready`。
  - 双 bank 写入将追上发送 bank 时暂停输入；已有行 pending 时不重复接受新的行结束。
  - 允许当前行启动与 `I_pkt_end` 同周期处理，避免产生额外 overflow。
- `fpga/uisrc/01_rtl/csi2/csi2_tx_top.v`
  - 用 relay token 状态和 packetizer ready 共同驱动 DDR cache 的 `out_ready` 和 token 读取。
  - 只有实际消费 token 时才写入 TX packetizer。

## 板级验证顺序

用户 RAM 下载 R36 后，先保持 COM16 诊断串口，连续观察至少数秒：

1. `DI=1` 且 `DE=0`：DDR 初始化仍正常。
2. `DC/CF` 持续增长：帧提交和帧消费仍在进行。
3. `RF` 应保持 `0`，或至少不再从 `0` 变为 `1`。
4. `TE/TXE` 应为 `0`；若仍为 `1`，继续记录第一次置位时刻。
5. `TP/TL` 应接近完整帧行数 1080，而不是 R35 的约 `0x19B`。
6. `TB` 应接近完整 1920x1080 RAW10 帧的字节量级；结合 `DL=1`、`RDY=1` 判断 DPHY 输出是否正常。

若上述计数正常但 A 板仍黑屏，再单独检查 A 板接收复位、帧尺寸和显示侧时序；不要把 R36 的离线 STA 结果当作板级视频已经恢复的证据。

## R36 板级复测

用户已将 R36 bit 下载到 FPGA RAM，我通过 COM16、115200 8N1 连续采集约 5 秒，共收到 39 条状态行。代表值如下：

```text
DI=1 DC=2040 DP=0000 ... TP=043A TL=0438 TB=0027A658 TE=0
... RF=1 ... DL=1 RDY=1 DB=1 DE=0 TXE=0
DI=1 DC=20D2 DP=0000 ... TP=043A TL=0438 TB=0027A658 TE=0
... RF=1 ... DL=1 RDY=1 DB=1 DE=0 TXE=0
```

判读：

- `DI=1`、`DE=0`、`DP=0`：DDR 初始化、缓存错误和帧丢弃均正常。
- `DC` 从 `0x2040` 增长到 `0x20D2`，`CF` 同步增长：帧持续提交并完成消费。
- `TP=0x043A`（1082）、`TL=0x0438`（1080）：TX 已经达到完整 1080 行，不再是 R35 的约 `0x19B` 行。
- `TB=0x27A658`（2,598,488 字节），接近 1920x1080 RAW10 的 2,592,000 字节有效载荷，差值属于帧/行传输统计口径差异范围。
- `TE=0`、`TXE=0`：当前没有 TX packetizer overflow 或字节数错误。
- `DL=1`，`RDY` 在采样中短暂为 0 后恢复为 1：DPHY 已锁定，ready 短暂波动未造成 TX 错误。
- `RF=1`：relay FIFO 的历史满标志已经置位；它是粘滞诊断位，不能单独证明当前仍在丢 token。由于 `TE/TXE=0` 且 `TP/TL` 完整，当前反压已经阻止了实际 TX 溢出。

本次板测说明 R36 已解决 R35 暴露的 DDR 回读到 TX packetizer 的吞吐失配，完整帧正在被送入 MIPI TX。之后用户提供了 17.77 秒的 HDMI 录屏 `C:/Users/pc/Videos/2026-10-31 14-32-47.mkv`。抽查 0、5、10、15 秒帧时，HDMI/MIPI FPS OSD 固定，而底层视频的水平拼接边界持续向上移动：缩放抽帧中的边界约从 y=245 移到 y=80（图像高 601 像素）。所以 B 板已发送完整帧，但端到端显示仍有垂直滚动/拼接故障。下一步应检查 A 板 CSI 接收的 FS/FE、line WC/行计数、接收复位和 DDR 显示读写帧同步；不能将问题认定为已经完全修复。
