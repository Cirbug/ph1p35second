## R35 新增字段

在原有一行状态后追加：

| 字段 | 含义 |
|---|---|
| `DI` | DDR 初始化/校准完成 |
| `DC` / `DP` | 已提交帧数 / 丢弃帧数 |
| `BR` | DDR 缓存中可读帧数 |
| `RQ` / `RR` | DDR 读请求数 / 返回数据数 |
| `CW` / `CL` / `CF` | 缓存输出 word / line / frame 计数 |
| `RW` / `RC` / `RF` | Relay FIFO 写入 / 读出数 / 曾经满标志 |
| `TXW` / `TXL` | TX packetizer 接收 word 数 / 完成的 RAW10 行包数 |
| `DL` / `RDY` | TX DPHY DPLL 锁定 / TX ready |
| `DB` / `DE` / `TXE` | DDR cache busy / DDR cache error / TX packetizer error |

这些计数用于确认数据流经过的最后一级。跨时钟域状态通过两级同步器送到 UART 域；连续日志中应以“是否持续增长、是否由零变非零、错误位是否置位”定位边界，单次采样瞬间的计数不作精确计量。

## 板级定位顺序

1. `DI=0`：先查 DDR 初始化/校准；`DI=1` 但 `DC=0`：没有完整帧提交到缓存。
2. `DC>0` 但 `RQ=0`：缓存读侧没有启动；`RQ>0` 但 `RR=0`：查 DDR 读返回；`RR>0` 但 `CW=0`：查缓存回读/输出状态。
3. `CW/CL` 增长但 `RW=0`：查 relay token 生成；`RW` 增长、`RC=0`：查跨域 FIFO、TX 时钟或复位。
4. `RC>0`、`TXW=0`：查 token 解包；`TXW>0`、`TXL=0`：查 CSI TX packetizer 输入和行包完成。
5. `TXL>0` 但 A 板仍无图像：结合 `DL`、`RDY`、`TXE` 和原字段 `T` 判断 DPHY 时钟、ready 和实际 HS 输出。

## R35 板级复测结果

用户已将 R35 bit 下载到 FPGA RAM，我通过 COM16、115200 8N1 连续读取了多组状态行。三条连续样本的代表值如下：

```text
DI=1 DC=205F DP=0000 BR=0 RQ=FFFF RR=FFFF CW=FFFF CL=FFFF CF=205F
RW=FFFF RC=FFFF RF=1 TXW=FFFF TXL=FFFF DL=1 RDY=1 DB=1 DE=0 TXE=1
TP=019D TL=019B TB=000F16CA TE=1

DI=1 DC=2063 DP=0000 BR=0 RQ=FFFF RR=FFFF CW=FFFF CL=FFFF CF=2062
RW=FFFF RC=FFFF RF=1 TXW=FFFF TXL=FFFF DL=1 RDY=1 DB=1 DE=0 TXE=1
TP=01A0 TL=019E TB=000F32FC TE=1
```

判读：

- `DI=1`、`DE=0`，DDR 已完成初始化且没有报告 DDR cache error。
- `DC/CF` 持续增长，说明帧已经提交并被读侧消费；`DP=0` 表示没有因完整帧提交失败而丢帧。
- `RQ/RR/CW/CL/RW/RC/TXW/TXL=FFFF` 是 16 bit 饱和计数，表示对应路径累计超过 65535，不能把它们当作当前帧精确计数。
- `RF=1` 是 relay token FIFO 曾经满；`TE=1` 和 `TXE=1` 表示 TX packetizer 曾检测到 overflow 或字节数错误。由于 `A_LINE_WC=2400` 为偶数且 2-lane 缓冲容量为 2048 个 16-bit word，当前更符合 overflow，而不是 WC 奇数错误。
- `DL=1`、大多数样本 `RDY=1`，DPHY DPLL 和 ready 已经起来；`TP/TL` 只有约 0x19C 行，远小于 1080 行，`TB` 约 1 MB，也低于完整 1920x1080 RAW10 帧的约 2.59 MB。

因此 R35 已把故障边界缩小到 **DDR 回读之后的 relay FIFO/TX packetizer 吞吐**。当前设计在 DDR 读侧以远高于 MIPI TX 消费速率输出整帧，relay FIFO 和单行乒乓缓冲无法长期吸收速率差，先发生 FIFO 满和 packetizer overflow，A 板收到的是不完整帧。下一步应在 RTL 中给 DDR 回读增加 TX 反压/行级节流，或扩大/重构 relay 缓存；在修改前不要把当前 R35 当作完整视频修复版。

## 当前板测边界

R34 的旧记录仍只证明 RX 和 crop/scale 有活动，不能定位 DDR/TX 阻塞；R35 已完成 RAM 下载和 COM16 诊断复测，但视频仍未恢复。下一步应针对已确认的 DDR 回读到 TX packetizer 的速率失配修改 RTL，重新做仿真、时序门禁和 RAM 板测。
