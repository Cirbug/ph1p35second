# HTS 1600 试改（2026-10-30，在原始仓库 ph1p35second 上）

## 改了什么

只有一个文件、两个字节：

```
fpga/uisrc/01_rtl/uics500_cfg/uics500reg.v
  29: 0x320c  0x0b -> 0x06
  30: 0x320d  0x24 -> 0x40
```

即 **HTS 由 0x0B24 (2852) 改为 0x0640 (1600)**，其余（输出窗口 1920×1080、
VTS 0x0467=1127、0x36FD=0x14）都不动。

备份：`uics500reg.v.bak_hts2852`。`git diff` 只有这两行。

## 依据

A 板工程当年在 2592×1944 下实测到 `MIPI FPS 030`，它用的就是
**HTS=0x0640(1600) / VTS=0x07D0(2000)**；而 B 板一直是 HTS=2852。

行时间 ∝ HTS，帧率 ∝ 1/HTS：

```
A 板：  1600 × 2000 × 30fps ≈ 96 MHz
B 板：  2852 × 1127 × 20fps ≈ 64 MHz   (当前实测)
若 VTS 被钳到 2000：2852 × 2000 × 20fps ≈ 114 MHz
```

两者像素时钟在同一量级，差别主要在 HTS。所以先把 HTS 拉到 A 板那个已验证的值。

## 预期与判断

| 实测 MIPI FPS | 含义 | 下一步 |
|---|---|---|
| 028 ~ 036 | 方向正确 | 按 `新HTS = 当前HTS × 实测fps / 30` 微调到正好 030 |
| ≈ 050 | VTS 没被钳，按 1127 生效 | 把 VTS 抬到 ~1900，让 30fps 落下来 |
| 仍是 020 / 黑屏 | HTS 不是那个杠杆 | 立刻回退：`Copy-Item uics500reg.v.bak_hts2852 uics500reg.v` |

## 注意

- 输出宽度仍是 1920（`0x3208/09=0x0780`），所以每行 WC 仍是 2400、`2400%4=0`，
  A 板不会因为这次改动丢行。
- HTS 变小不影响 B 的发送速率（B 的 TX 上限约 52fps），但若帧率冲到 40+，
  B 的令牌 FIFO 压力会变大，留意 K17 错误灯。
