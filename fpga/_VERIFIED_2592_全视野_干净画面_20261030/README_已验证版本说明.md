## 三、关键参数（改动过的地方）

### B 板 `uics500reg.v`（摄像头寄存器表，Motorola 111 条）

| 寄存器 | 值 | 含义 | 为什么 |
|---|---|---|---|
| `0x320C/D` | `0x0FA0` = **4000** | HTS | **链路负载 94%→39%**，这是画面干净的关键 |
| `0x320E/F` | `0x07D0` = **2000** | VTS | 帧率 13.5fps（HTS 4000 时） |
| `0x3E00` | `0x02` | 曝光高 4 位 | 原表只写了 0x3E01 → 曝光最大 255 行，画面全黑 |
| `0x3E01` | `0x58` | 曝光低 8 位 | 曝光 = 0x258 = **600 行**（原 249 行太暗） |

### B 板 `csi2_tx_top.v`

| 参数 | 值 | 说明 |
|---|---|---|
| `CROP_EN` | **0** | 必须不裁剪：A 的 `video_rx_integrity` 要求正好 1944 行 |
| `LANE_SWAP` | **1** | 0 会黑屏（实测） |
| `CLK_LANE_MODE` | **`"INTERRUPT"`** | **这是能出画面的第一个突破点**，CONTINUE 时 A 只在开机锁一次 |
| `DPLL_MULTI_RATIO` | **17** | 900 Mbps（A 的 SDC 上限） |
| `HS_OUTPUT_VOD` | **250mV** | 最大摆幅 |
| `HS_OUTPUT_DE_EMPHASIS` | **0dB** | |
| `FRAME_LINES` | **1944** | 按摄像头送来的行数合成 FS/FE |
| 帧边界 | **B 合成** | 摄像头在 2592 模式下**不发 FS/FE**（实测 F=0 证明） |

## 四、三个已确诊的 Bug（踩过的坑）

| # | Bug | 现象 | 修复 |
|---|---|---|---|
| **1** | `BUF_AW = 10`（1024 字）装不下一行 1620 字 | **每行后 36% 是错数据，但 WC 仍报 3240 → 所有计数校验都通过，图像却乱** | `BUF_AW = 12` |
| **2** | HTS 1600 → 链路利用率 **94%** | 位错误（A 收到 `0x0C` 变成 `0x4C`）；竖条纹 | HTS **4000**（39%） |
| **3** | 曝光只写了 `0x3E01`（249 行），没写 `0x3E00` | 画面全黑（按 AE 键能变亮但会卡死） | `0x3E00=0x02, 0x3E01=0x58` = 600 行 |

## 五、千万不要做的事

| ✗ 不要 | 原因 |
|---|---|
| **给 A 加 I_clk_lane_in_delay 自动扫描** | 扫描逻辑会让延时在 0~63 之间跳变 → A 的 DPHY 永远采不到数据（`CC=0`、`last_words=0`）|
| **`LANE_SWAP = 0`** | 直接黑屏 |
| **`CLK_LANE_MODE = "CONTINUE"`** | A 的 RX 只在开机锁定一次，之后再也不认包 |
| **B 裁剪后再发给 A** | A 的 `video_rx_integrity` 零容差：必须正好 1944 行、每行正好 3240 B |
| **在 B 里配 1920 输出表**（F02 表）| 那张表采样窗口是 1928×1088 → 只用了传感器 41% 面积 → **画面放大 1.35 倍** |
| **直接对接两板的 3.3V** | 两个稳压器并联，会打架 |
| **让 B 的 UP 帧率超过链路能力** | 94%=严重条纹，49%=轻微条纹，**39%=干净** |

## 六、还没解决的问题

### ① 画面一下白一下绿（白平衡抖动）

- 不是数据传输问题（撕裂已消失，数据干净）
- 怀疑 A 的 `awb` 模块在大面积白色场景下抖动
- **验证方法**：进 A 的 UI「图像调整」菜单，关掉/固定 AWB，看是否停止
- 还没试

### ② 延迟 117 ms

- `CAM 083.3 ms` = 摄像头帧周期（1/13.5fps，正确）
- `LAT 117.6 ms` ≈ 1.4 帧 = 帧缓冲架构固有延迟
- 降低办法：提高帧率（但要牺牲链路余量 → 条纹回来）

### ③ 帧率只有 12 fps

- 用 HTS 4000 换来的画面干净
- 平衡点：HTS 3200 → 17fps / 49%（轻微条纹）；HTS 4000 → 13.5fps / 39%（干净）

## 七、"放大 1.35 倍"问题（已解决）

早期用 F02 的 1920 表时，摄像头只采样中间 1928×1088 → 视野 41%，画面放大 1.35 倍。

**现在改成 2592 全采 + A 缩放** → 全视野、无放大 ✓

如果以后要让 B 自己缩放（A 保持 1920），需要写 RAW10 拆包/重打包的流式缩放器：
- 水平 2592→1920 = 20/27，**周期 108 像素，不是 8 的倍数** → **无法在 16bit 字级别实现**，必须做 10bit 像素级
- 垂直 1944→1080 = 5/9，只丢整行，零成本
- 估计 200~300 行 + 仿真，1~2 天

### A 的 `BC` 寄存器解码

```
bit[11:0]  = last_words   （2592 模式应为 810 = 3240B/4）
bit[23:12] = last_lines   （应为 1944）
bit[31:24] = last_errors
     bit0 = lane_error
     bit1 = match_error   （常态置位，可能无害）
     bit2 = bad_line
     bit3 = 缺 EOF
     bit5 = packet_error
0xb8: [31:16]=坏帧数  [15:0]=好帧数
```
