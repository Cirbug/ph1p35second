## 代码中确认的问题与边界

原本 B 板的 `cnn_raw10_resize_bin.v` 从 RAW10 提取某个 Bayer 像素的高 8 位，立即按固定 128 阈值生成 0/255。
这不是去马赛克后的灰度，也不包含 A 板显示前的 ISP/gamma/数字亮度处理。
检测器后续又按 128 判断，但接收的是已有的 0/255，无法恢复第一次二值化已经丢掉的亮度。

结合当前大面积黑 mask，固定阈值不适合当前 RAW 亮度是重点修复方向。
仅凭二值 mask 不能反推原始 RAW 的灰度分布，也不能据此排除 Bayer 采样、RAW 解包或曝光控制的其他问题；因此同时加入灰度采样诊断。
本轮不修改 A 板、传感器曝光寄存器、曝光控制链路、DDR 缓存、裁剪尺寸或 CNN 权重。

## R50 改动

### 1. 自适应阈值

在 320×180 缩小采样阶段，累计上一个完整采样帧的 32 档亮度直方图。
用 75% 分位所在 bin 的中心估计纸面背景，令阈值为其 3/4，下限为 8。
阈值在每一帧首像素锁存，整帧保持一致。此机制只调整 CNN 预处理，不改变摄像头曝光。

例如：背景 bin 中心 84 时阈值为 63；背景降至 bin 中心 36 时阈值降至 27。
初始阈值仍为 128。曝光突然变化时有上一帧统计带来的响应延迟；持续过暗、无对比度或大面积非纸面背景，仍可能使识别失败。
这是待上板验证的预处理修订，不能预先宣称已经恢复 1/2/3 分类。

### 2. 同一被接受帧的两种输出

- 图像通道 0：320×180 的实际检测 mask，57600 字节，黑字白底。
- 图像通道 1：80×45 的 RAW 高八位采样缩略图，3600 字节，用于观察二值化之前的亮度。
- 灰度缩略图只在检测器实际接受写入 mask 的像素上采样；与 mask 共享发送期间的帧保持机制。
- 灰度缩略图采用 4×4 中的一点抽样，不是原始全幅灰度，也不是 A 板 ISP 后的亮度图。
- 缩略图增加两个 ERAM20K，不增加一个完整 320×180 的 8 位缓存。

UART 协议：

```text
image:0,57600,320,180,24\n
[57600 字节 mask]
image:1,3600,80,45,24\n
[3600 字节采样灰度缩略图]
```

115200 / 8N1 下，两张图的纯传输时间约 5.32 秒；采帧、检测和状态机开销另计。这是静态诊断抓帧，不是实时视频预览。

### 3. 不依赖 VOFA 的电脑接收器

`fpga/tools/capture_cnn_uart.py` 直接接收并保存 PNG、原始串口字节与 JSON 统计，也支持离线解码已有抓包。
已用实际 R49 捕获回放，成功还原三幅图片并重现上述黑像素占比。
脚本只接收，不发送控制指令、不编程 FPGA/Flash，串口打开前设置 DTR/RTS 为关闭。

使用已有电脑环境：

```powershell
& 'E:/conda/python.exe' 'D:/2026fpga/ph1p35second/fpga/tools/capture_cnn_uart.py' --port COM16 --seconds 22
```

运行前关闭占用 COM16 的 VOFA/其他串口软件。默认保存至 `fpga/cnn_captures/<时间>/`。

## 上板验收

1. 最终时序与 bit 核验后，由用户下载 B 板 RAM。
2. 直接串口抓取 mask 和 RAW 缩略图；至少看三个成对样本。
   初始阈值仍为 128，第一幅 mask 可能仍偏黑；应接收 15–22 秒观察后续自适应帧，而不是用第一幅就判定无效。
3. 检查纸面是否从大面积黑色恢复为白色、数字笔画是否仍连续，并比较两种亮度条件。
4. 再检查数字定位/类别。若灰度中已有条纹、错位或无对比度，继续查 RAW/采样/曝光，而不是继续调分类权重。

本轮未执行 RAM 下载、Flash 写入或 MCU 调试；没有创建 worktree、切换分支或移动工程。

### 同份 RTL 的离线分割/分类回放

新增 `fpga/uisrc/02_sim/tb_cnn_captured_mask.v`，把板端捕获的第一幅 mask 输入当前检测器和 CNN RTL。
在运行前逐字节确认仿真 HEX 与硬件使用的两个 MIF bank 共 4096 字节完全一致。
仿真权重 CRC `EEC8E020`，与 Python 对同一 4096 字节计算的 CRC32 一致。

```text
RTL_DIGIT x=60  y=26  w=14 h=61 class=1 patch_crc=749cac7c
RTL_DIGIT x=108 y=35  w=54 h=66 class=3 patch_crc=ff307182
RTL_DIGIT x=184 y=56  w=40 h=65 class=3 patch_crc=16388d82
RTL_DIGIT x=290 y=125 w=30 h=55 class=8 patch_crc=fe8934bd
RTL_FRAME_DONE count=4 reported=4 weight_crc=eec8e020
```

对照图像：手写 1→1、2→3、3→3，右下角阴影→8。
因此不能宣布 CNN 已经准确识别：亮度预处理改善后，仍存在 2/3 分类错误及边缘阴影误检。
这只是当前 RTL 对真实板端输入的离线结果，**不是板端 UART 回传的类别**。
R50 当前 UART 输出的是诊断图像，尚没有这四项类别的板端回读证据。
