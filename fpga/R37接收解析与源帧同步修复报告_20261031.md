## 目标与当前边界

针对屏幕动态画面上下滚动/拼接，修复已在仿真复现的 B 板 CSI 连续包丢失，并让真实源 FS 重新对齐裁剪行起点。此前 A 板 C8 固定表示没有新增该诊断中的读空/未就绪事件；不能凭 C8 判断图像位置正确。

生产 RTL 已修改，10 项小尺寸/链路回归及全尺寸空间检查通过；TD 综合、布局、布线、慢/快角 STA 和 bit 生成均完成。板上真实摄像头 HS 包分组尚未重新测量，所以不能宣布本次变更已经解决实际滚动。

保持传感器 2592×1944、B 板缩放/裁剪后 1920×1080 写 DDR、DDR 分给 A 板和本地 CNN 支路的结构。A 板 FPGA、MCU、引脚、时钟约束、传感器寄存器表和 UART 字段布局本轮未修改。没有执行 FPGA RAM 或 Flash 烧录。

## 修改

1. `fpga/uisrc/01_rtl/csi2/csi2_rx_parse.v`
   - 原来只在 HS valid 上升沿读取包头；改为按 WC/CRC 边界继续读取同一 HS 区间内的后续包。
   - 使用已有 `csi2_ecc` 检查包头；拒收坏 ECC、奇数字节长包及零长度 RAW10。
   - 仅将 VC0 RAW10 载荷送入裁剪器，正确跳过嵌入数据、其他 VC 和 LS/LE 短包。
   - LP 到来时结束被截断的包，下一 HS 从新包头恢复；截断 RAW 行会产生行结束，供裁剪器检查短行并复位组装计数。
   - 按 A 板已经使用的 SC500 防护策略，包间遇到 00/FF 尾部填充后停止解析；FS 只允许出现在 HS 区间的第一包，避免全零尾部伪装成零帧号 FS。FE 后等待下一个 HS。
   - CRC 两字节仍只消费、不校验；ECC 只检错拒收，不纠错。`O_wc_err` 现在涵盖包头/截断错误，保持复位清除的粘滞位语义。
2. 同文件新增 `csi2_raw_frame_sync`，在现有已注册源文件内实现，不调整工程源文件体系。真实 FS 优先复位源行计数，并让裁剪器结束旧片段、重新从行 0 开始。保留无 FE 时的 1944 行回退边界。
3. `fpga/uisrc/01_rtl/csi2_tx_top.v` 将原来只按累计行数组帧的逻辑替换为上述同步模块。裁剪器使用同步后的边界重新对齐。
4. `fpga/uisrc/01_rtl/csi2/csi2_raw10_scale_crop.v`
   - 修复 RAW10 第五字节位于 16-bit 输入高字节时，错误地从低字节读取最低两位的问题；同时按标准 P0..P3 顺序取低两位，与 A 板 RAW10 解包顺序一致。
   - 源 FS 用作旧片段结束/重新对齐时，如果此前没有打开可见裁剪帧，只复位坐标，不产生空 FE；防止空帧污染统计。

最低两位错误已由逐字节测试发现并修复，但它本身不足以解释大幅画面滚动。实际滚动根因仍需 RAM 下载后的板测确认。

## 仿真

复现入口：


该脚本同时检查进程退出码、PASS 标记及 FAIL/FATAL 文本，避免旧测试仅打印 FAIL 却退出 0 的误判。

通过的 10 项：

- `tb_csi2_rx_shared_hs_probe`：独立 HS、共享 HS 的 FS/RAW/FE 均识别。
- `tb_csi2_rx_recovery`：连续多行、非零帧号、尾部 00/FF、坏 ECC、包头截断、载荷截断、缺 CRC、其他 VC/嵌入包、LS/LE、奇数 WC 和下一 HS 恢复。
- `tb_csi2_rx_frame_sync`：半帧启动和不完整旧帧后收到真实 FS，逐字节检查输出源行及水平 Bayer 对抽取，包含不对称低两位；同时检查没有孤立/重复 FE。
- `tb_csi2_rx_parse`、`tb_csi2_pipeline`：原有解析和收发载荷/包头/CRC 回归。
- `tb_csi2_raw10_scale_crop`、`tb_csi2_scale_tx`：缩放裁剪和无 FS/FE 时的发送链路回归。
- `tb_ddr_triple_frame_cache`、`tb_csi2_crop_ddr_fanout`：DDR 缓存、反压、partial-frame abort 和 CNN 分支回归。
- `tb_dbg_uart_frame_stats`：原 320 字节 UART 布局保持。

旧 `tb_csi2_scale_tx` 原本给 RAW10 包头填入零 ECC；既然现在真实检查 ECC，已将测试激励修正为正确的 `WC=40, DI=2B, ECC=1B`。

## 板测步骤

最终 bit 和时序通过后，仅将 B 板新 bit 下载到 **RAM**，A 板及 MCU 暂保持现状，不写 Flash。观察屏幕是否仍有动态拼接边界移动，并读 B 板 115200 UART 连续几秒：

1. 首先看 `FS/FE` 是否持续增长。它们现在来自解析器真正识别的短包，不是人工推导出来的帧边界。如果仍无真实 FS/FE，不能仅凭 TX 1080 行就认定源帧对齐。
2. 若 FE 可识别，`RI` 应为 `0798`（1944 行）、`IW` 为 `0CA8`（每行 3240 字节）；`RE` 检查坏行统计。`RD` 是旧的原始包头探针所见 FE 累计计数，不是行数。`RXE` 是粘滞解析异常标志，需结合启动和后续日志解释。
3. 缩放输出应为 1080 行、WC=2400；TX `TP=043A`、`TL=0438`、`TB=0027A658`、`TW=0960`，`TE/TXE` 不应出现新错误。
4. `DI=1`、`DC/CF` 增长，结合 `DP/DE` 判断缓存状态。
5. A 板继续看 B8/C0 是否稳定增长、坏帧及拒绝帧是否新增。C8 不变表示没有新增该类显示异常，不能充当画面空间正确的证明。

本轮尚无新串口采集：检查时系统没有枚举出串口设备。未经用户 RAM 下载及实际屏幕验证，不把“仿真/STA/bit 生成”记为“视频已修复”。
